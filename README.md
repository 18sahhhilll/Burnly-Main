# Burnly — Startup Planning & Financial Intelligence Platform

**Burnly** is an AI-powered financial simulation and intelligence platform built for startup founders and venture capital analysts. Founders enter their startup's key business parameters once—such as starting cash, revenue, burn rate, headcount, and growth targets. Burnly then performs two core functions:

1. **Deterministic Financial Simulation**: Calculates 36-month financial projections, cash flow trajectories, runway duration, zero-cash month timing, break-even milestones, funding needs, and financial risk scores purely in code (0% LLM hallucination).
2. **Generative Intelligence Reports**: Consumes those exact simulation numbers alongside startup context to generate five structured intelligence reports powered by Google Gemini with real-time Google Search grounding.

---

## 🏛️ Architectural Overview & System Design

Burnly uses a **Dual-Engine Architecture** to guarantee financial trustworthiness while leveraging generative AI reasoning.

```
+-------------------------------------------------------------------------+
|                              FRONTEND                                   |
|   React + Tailwind CSS + Lucide Icons + Recharts (Dark Cockpit UI)      |
|                                                                         |
|  +---------------------------------+  +------------------------------+  |
|  |    Deterministic Simulation     |  |     Profile Intake Wizard    |  |
|  | (Runway, Burn, Break-even, Risk)  |  |  (Business, Team, Financials)|  |
|  +---------------------------------+  +------------------------------+  |
+-------------------------------------------------------------------------+
                                    |
                         REST API Calls (Bearer JWT)
                                    v
+-------------------------------------------------------------------------+
|                              BACKEND                                    |
|              Express.js + Mongoose + Node.js HTTP Server                |
|                                                                         |
|  +--------------------+  +--------------------+  +-------------------+  |
|  | Auth & Security    |  | Shared Simulation  |  | Deterministic     |  |
|  | (Sessions, JWT,    |  | Math Engine        |  | Consistency       |  |
|  |  Cookies, RateLim) |  | (projections.js)   |  | Enforcer          |  |
|  +--------------------+  +--------------------+  +-------------------+  |
|                                     |                                   |
|                          Calls Google Gemini API                        |
|                                     v                                   |
|            +-------------------------------------------------+          |
|            |  Google Gemini 1.5 Flash + Search Grounding API |          |
|            +-------------------------------------------------+          |
+-------------------------------------------------------------------------+
```

### Dual-Engine Philosophy
- **Financial numbers** (runway, starting cash, net burn, break-even month, funding ask) are **never generated by the LLM**. They are calculated using pure JavaScript functions (`simulationEngine.js`, `projections.js`, `riskScorer.js`).
- **Narratives and analysis** (TAM/SAM/SOM, market trends, competitor mapping, pitch deck slides, execution roadmaps, qualitative risks) are generated by **Google Gemini 1.5 Flash**. The LLM receives the exact computed financial figures as immutable system facts, preventing hallucinated financial numbers.

## 🚀 Tech Stack

### Frontend
- **Framework**: React 18 with Vite

### Backend
- **Runtime**: Node.js ES Modules (`"type": "module"`)
- **Framework**: Express.js
- **Database**: MongoDB via Mongoose

### AI Integration
- **LLM**: Google Gemini 1.5 Flash (`@google/generative-ai`)
- **Grounding**: Google Search Grounding (`tools: [{ googleSearch: {} }]`) for market research and citations

## 📑 Top-Level Navigation & Core Modules

Burnly is organized into 9 top-level modules accessible via the top navigation bar (`ModuleNav.jsx`):

```
1. Cockpit   2. Wizard   3. Projections   4. Compare   5. Market   6. Competitors   7. Roadmap   8. Pitch   9. Risk
```

### 1. Financial Cockpit (Dashboard)
- **Metrics Overview Cards**: Real-time display of Starting Cash (₹), Monthly Revenue (₹), Net Monthly Burn (₹), Computed Runway (months), Break-Even Target, and Financial Risk Bucket (Low/Medium/High).
- **Financial Input Form**: Interactive form with live sliders and inputs for starting cash, revenue, growth rate %, payroll spend, marketing spend, infrastructure spend, ops spend, founder salary, planned raise, and dynamic hiring timeline additions.
- **Visual Projection Charts**: Interactive 36-month runway trajectory chart, revenue vs. expense break-even chart, and monthly net burn breakdown.
- **Risk & Action Suggestions Panel**: Rules engine generating immediate corrective suggestions (e.g., "Freeze non-essential hiring", "Reduce marketing spend by 15% to extend runway past 12 months").

### 2. Startup Profile & Intake Wizard (`ProfileWizard.jsx`)
A 4-step onboarding intake flow where founders define their startup once:
- **Step 1: Business Overview**: Venture name, one-liner, problem statement, industry, target customer, stage (Idea, Pre-Seed, Seed, Series A, Growth), and target geography.
- **Step 2: Team & Headcount**: Number of founders, total headcount, key department roles covered.
- **Step 3: Financial Snapshot**: Baseline starting cash, monthly revenue, revenue growth rate, expense categories, founder salary, funding raised, and target raise amount.
- **Step 4: Revenue & Unit Economics (Optional)**: ARPU/pricing, active customer count, monthly churn rate %, Customer Acquisition Cost (CAC), and Gross Margin %.
- **Sample Startup Data**: Includes a one-click "Use Sample Startup Data" preset (PayFlow India) for instant previewing.

### 3. Financial Projections & Scenario Modeling (`ProjectionsView.jsx`)
- **Scenario Variants Generator**: Auto-generates **Base**, **Conservative** (-20% growth, +15% burn), and **Aggressive** (+30% growth, -10% burn) 36-month projections side-by-side.
- **Target Buffer Funding Needs Calculator**: Identifies the exact capital raise required (₹) and target close month needed to maintain a default 6-month cash buffer.
- **Sensitivity Analysis Engine**: Ranks financial variables (Payroll, Growth Rate, Marketing Spend, ARPU) by their degree of impact on runway months ($\pm 20\%$ variance).
- **Unit Economics Breakdown**: SaaS LTV, Monthly Churn Dollar Loss, Gross Margin Gross Profit, and LTV:CAC ratio.

### 4. Scenario Comparison Matrix (`ScenarioComparison.jsx`)
- Compare up to 4 saved scenarios side-by-side (e.g., "Base Hiring Plan" vs. "Aggressive Marketing Blitz" vs. "Conservative Survival Plan").
- Highlights key metric differences in green/red (Runway, Zero-Cash Month, Total 36-Month Revenue, Total Cash Spent).

### 5. Market Intelligence Report (`ReportView` type="market")
- **Visual TAM / SAM / SOM Cards**: Total Addressable Market, Serviceable Addressable Market, and 3-Year Obtainable Target with explicit calculation assumptions.
- **Key Industry Trends & Market Drivers**: Ranked trend signals with provenance tags.
- **Strategic Growth Opportunities**: Tailored growth vectors aligned with current runway.

### 6. Competitor Mapping Report (`ReportView` type="competitors")
- **Competitor Comparison Table**: Direct competitors with positioning, pricing models, key strengths, and vulnerabilities.
- **"Gaps You Can Own" Card**: Underserved market segments your venture can win.
- **2-Axis Market Positioning Map**: Visual grid mapping price vs. feature complexity and plotting target venture positioning against competitors.

### 7. Execution Roadmap Report (`ReportView` type="roadmap")
- **First 90 Days Priorities**: Pre-close milestone targets with explicit metric checkpoints.
- **Runway-Driven Execution Phases**: Phase 1 (PMF, Months 1-6), Phase 2 (Scale, Months 7-18), Phase 3 (Expansion, Months 19-36).
- **Simulation Hiring Triggers**: Links milestone milestones to hiring events calculated in the simulation engine.

### 8. Full 8-Slide Investor Pitch Deck (`ReportView` type="pitch")
Generates an 8-slide pitch outline auto-filled with financial snapshot numbers:
1. Title & Vision
2. The Problem
3. The Solution & Product
4. Market Opportunity
5. Traction & Validation
6. Business Model
7. Financial Model & Projections (Auto-filled with 36-month simulation math)
8. The Ask & Capital Allocation (Auto-filled with computed recommended raise amount)

### 9. Risk Intelligence Report (`ReportView` type="risk")
- **Deterministic Financial Risk Score**: 0-100 score + bucket (Low, Medium, High Risk) derived from runway months and burn ratio.
- **Qualitative Risk Matrix**: $3 \times 3$ Severity $\times$ Likelihood visual matrix (High/Med/Low Severity vs. High/Med/Low Likelihood).
- **Risk Mitigation Action Items**: Specific qualitative risk factors across Regulatory, Execution, and Market Timing categories paired with concrete mitigation steps.

## 🔒 Security, Trust & Hardening Systems

### 1. Grounding & Per-Claim Source Integrity
- Grounded web search retrieval results from Google Gemini are extracted from `groundingMetadata.groundingChunks`.
- `sanitizeProvenance()` parses claims in generated reports and checks segment-level grounding text. Claims are kept as `"Sourced"` **only** if grounding segments back that specific text; unlinked claims fall back to `"Estimate"`.
- Grounding URLs are cleaned of Google redirect wrappers and restricted strictly to `http://` or `https://` protocols in `ReportView.jsx`.

### 2. Multi-Session Auth & Token Rotation
- **Access Tokens**: Short-lived (30-minute) JWTs passed in HTTP `Authorization: Bearer <token>` headers.
- **Refresh Tokens**: Long-lived (7-day) cryptographically random tokens stored in `httpOnly`, `SameSite=Lax` cookies.
- **Database Hashing & Rotation**: Refresh tokens are stored as SHA-256 hashes in a `sessions` array in `User.js`. Each refresh request rotates the token.
- **Reuse Detection & Emergency Revocation**: If a used or revoked refresh token is presented, all sessions for that user account are wiped immediately.
- **Account Deletion Isolation**: `DELETE /api/auth/me` cascades to delete user records, ventures, scenarios, and reports while isolating other user data.

### 3. Prose Consistency Enforcer
- Free-text descriptions and slide headlines generated by the LLM are passed through `walkAndSanitizeProse()` in `reportService.js` to ensure generated prose does not contradict true simulation runway figures.

### 4. Security Headers & Payload Controls
- Installed `helmet()` middleware for standard web security headers.
- Payload body size capped to `100kb` (`express.json({ limit: '100kb' })`).
- NoSQL injection sanitizer strips keys starting with `$` or containing `.`.

### 5. Rate Limiting & Atomic Daily Usage Cap
- **Rate Limiters**: `authLimiter` limits authentication attempts to 20 per 15 minutes. `apiLimiter` caps standard API requests to 100 per minute.
- **Atomic Daily Counter**: `UserUsage` model tracks daily report generation per user using atomic MongoDB `findOneAndUpdate`.
- **Automatic Failure Refund**: If report generation throws an error (e.g., API timeout), `reportController.js` decrements/refunds the user's daily cap count automatically.

### 6. Third-Party Data Privacy Notice
- Before generating their first report, users see a modal explaining that business context is transmitted to Google Gemini servers, but personal credentials (email, password) are **never** shared.

## 🛠️ Local Development Setup

### 1. Prerequisites
- Node.js (v18 or higher)
- MongoDB running locally on `mongodb://localhost:27017/burnly` (or a MongoDB Atlas URI)
- Google AI Studio Gemini API Key (`GEMINI_API_KEY`)

### 2. Backend Setup
```bash
cd backend
npm install
cp .env.example .env
# Edit .env and configure MONGO_URI, JWT_SECRET, and GEMINI_API_KEY
npm run dev
# Server running at http://localhost:5000
```

### 3. Frontend Setup
```bash
cd frontend
npm install
npm run dev
# Vite dev server running at http://localhost:5173
```

### 4. Running Automated Test Suites
```bash
# Backend Tests (25 tests)
cd backend && npm test

# Frontend Unit Tests (19 tests)
cd frontend && node --test src/tests/*.test.js

# Frontend RTL DOM Component Tests (6 tests)
cd frontend && npm test
```

### 5. Production Build
```bash
cd frontend && npm run build
```
